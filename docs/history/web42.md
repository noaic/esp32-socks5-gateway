# web42：首次访问强制设置管理口令

2026-10-05。替代 web41 的随机口令/串口登录方式。代码、构建与本机测试完成，已烧录并通过启动验证；首次设置与浏览器登录验收进行中。原有 Web 管理功能、配置试运行和两客户端转发保留。不增加 BLE、OTA 或物理恢复按钮功能。

## 登录流程

1. 连接 AP，打开 `http://192.168.4.1/`。
2. 若尚未设置管理口令，首页仅显示首次设置表单。输入两次一致的 12～64 字节口令。
3. 设备端校验后保存 NVS，立即关闭首次设置入口，不重启、不更改当前网络配置。
4. 点击“打开管理页并登录”；使用固定账号 `admin` 与刚设置的口令。后续正常使用该口令登录。

未完成设置时，状态、配置和设备断开 API 返回 423，不允许绕过初始化直接保存配置。`POST /api/setup` 仅在未设置状态允许，成功后再访问返回 409，不是免认证修改密码入口。请求仍要求专用管理头、JSON、来源检查、AP 接口和子网限制；两个设置请求由单个 HTTP 任务串行处理，首个成功提交者完成设置。

首次设置时应只让自己的可信设备连接 AP。初始认领以 AP 接入权限为前提，没有依赖串口、云服务或额外一次性验证码。页面不强制整个 Wi-Fi 网络先完成认证，只限制管理功能；没有认证门户或设备自动弹窗。

设置完成后管理口令不打印、不通过状态/config API 返回。HTTP Basic 和未加密 NVS 的限制与 web41 相同。

## RST/EN 与恢复默认

**RST/EN 一般控制芯片复位，只会重启，不会清除 NVS、Wi-Fi 配置或管理口令。断电同样不会清除；普通应用重新烧录也通常保留 NVS。**

- 口令已设置：按 RST 后仍用原口令登录，不重新开放首次设置入口。
- 首次设置尚未完成：按 RST 后继续显示首次设置页。
- 网络配置正在试运行但没有确认：按 RST 后恢复上一份已确认配置；这是应用实现的配置回退，不是硬件恢复出厂。
- Web 页“恢复默认”保留管理口令，不等于清除口令。

当前没有已忘记口令时的免认证恢复入口。离线处理 NVS 可以恢复初始状态，但会涉及配置清除；不要把全 Flash 擦除当作普通重启。未来若确有需要，可单独设计带物理在场确认的恢复入口，再核对板上按键与 GPIO；本轮没有配置 BOOT 长按或多次 RST 清除行为。

### 发现的重启接入边界

03:42:33 Android 自动关联后未收到 `IP_EVENT_ASSIGNED_IP_TO_CLIENT`；已有 IP 流量触发 mapping_drop，而 client 注册项 IP 尚未建立。03:45:19 手动断开、03:45:28 重连后，03:45:29 DHCP ACK 事件把 `192.168.4.2` 登记为 token=4，随后测速服务收到页面请求。现象符合客户端缓存租约、重关联时没有立即发起 DHCP，不能仅以 Wi-Fi associated 判断可转发。

当前要求重启后手动重新连接；后续需要在保持 MAC/association token 隔离的前提下改善缓存租约恢复，不能直接取消 owner 校验或根据裸 IPv4 来源接纳未知设备。测速期间不修改固件，以免混合样本。
