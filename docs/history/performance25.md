# perf25：单路/四路并发基线（保持 perf23 固件）

## 修改与结构

仅tools/throughput_bench.html和tools/test_stream_server.py，没有修改ESP32源码/config，也没有build/flash。当前板子仍是已保留的perf23（perf24 flow内部RAM实验已撤回）。

页面保留单路并增加4路按钮，每种3轮、每条连接每方向8MiB；4路每轮下载/上传各32MiB，整组3轮96MiB/方向。四次fetch同时发起、HTTP端点关闭连接，应用上最多4条数据传输；浏览器调度和建连仍可能引入启动偏差，记录每条完成耗时辅助判断，不预先保证每毫秒都四条满速。

吞吐用整组成功完成总字节/(首请求开始至所有响应body完成的墙钟时间)，不用各连接速率相加或平均冒充总吞吐。内容校验在计时区间之外，下载逐字节验证每条、上传验证每条服务端SHA结果。四路共用组AbortController/120秒超时，任一失败时取消peer并await allSettled，然后再报告失败/重新启用按钮，避免残留请求污染下一轮。两个测试按钮均禁用到本次测试退出。

自动报告新增streams=1/4、total_bytes_per_direction、每轮download_stream_ms/upload_stream_ms；后端保留原JSONL并校验streams只允许整型1/4（拒绝bool等），兼容旧记录缺失streams视为1。每轮/完成报告仍在计时外，上报失败保留页面及重试按钮。

## 验证

Python编译检查通过。JS真实脚本模拟执行单路/四路：峰值并行请求1/4、分别6/24次传输，aggregate rate按总字节及组时长核对；模拟一条HTTP503时共享abort触发、所有peer drain结束后错误上报，按钮恢复。模拟不能替代Android实际浏览器。

临时HTTP后端验证1/4模式保存、非法streams(True/2/0)拒绝、最新HTML及label注入成功。主机服务已更新，仍用http://192.168.1.10:18080/bench、固件标签perf23-session-layout；本阶段记录bench-perf25-results.jsonl，服务/tmp/esp32-perf25-peer.log。串口继续monitor-perf24-rollback-live.log，不重开设备，避免无关复位。

## 测试与判断

Android保持现AP连接、移动数据关闭、停止其他业务，刷新页面先单路后四路；结果自动记录，不用用户抄数字。四路量比单路大，运行更长；比较相同固件当前基线，结合CPU、活动会话、两段队列、TCP重传、内部heap及最大块。

- 若总吞吐明显提升，支持单流窗口/调度/拥塞控制限制的可能性，但更多总数据及更长稳态也可能影响比较，不能立即归因为唯一因素。
- 若四路总吞吐接近单路、CPU饱和或两侧驱动/重传压力明显，优先找整体处理/空口限制，避免盲目增加窗口。
- 若并发降低速度或错误增多，优先调查公平调度、背压、内部内存/PCB容量及上游，不从单流均值推出应用体验。

四路最多会保留32MiB下载body及upload等浏览器内存，结束后释放引用；它是开发主机工具，不增加ESP32 Web UI。固定64会话/512映射、窗口及RX防积压修复均保持。真实两组结果尚待采集，不宣称速度提高。
